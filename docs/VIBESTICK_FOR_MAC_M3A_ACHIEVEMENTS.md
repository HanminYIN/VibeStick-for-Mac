## 1. 阶段结论

M3-A 把 M2 已经建立的安全配置通道，第一次完整用于用户每天真正看到的设备首页。结果不是单纯更换配色或放大字体，而是一套经过 Mac 高保真预览、固件实现、反复刷写和真实 135 × 240 LCD 肉眼校准的 Codex Focus 界面。

首页现在把最重要的信息压缩成四层：Wi-Fi、Bridge 与电量；Codex 当前状态和项目；动态额度窗口；同步、刷新和语音按键提示。项目名可以在 Mac App 中显示、隐藏或指定固定名称，隐藏后状态卡会重新放大和平衡，不会留下空洞区域。只有一个额度窗口时自动展开成全宽卡片；多个窗口时仍自动分栏。

M3-A 同时修复了两个会直接破坏“看起来正确”的数据问题：当前运行任务的项目名不会再被较新的已完成会话覆盖；额度默认继续使用低资源的 session 被动事件，只有使用者双击刷新时才发起一次主动读取，并用来源与时间戳防止旧读数覆盖新读数。

## 2. 从原作者版本继承并保持稳定的核心价值

以下能力由 Gary Zhang 的原始 VibeStick 奠定，M3-A 没有把它们包装成自己的发明，也没有为了新界面而替换稳定链路：

- StickS3 作为 coding agent 桌面状态终端的产品形态。
- Codex、Claude 等 provider 的状态、项目、额度和提醒数据模型。
- 正面蓝键长按录音、松开上传、ASR 转写和 Mac 文字输入。
- 录音全屏覆盖层、波形动画和设备提示音。
- Bridge HTTP 服务、Mac HUD 和 Paste 链路。
- OpenAI-compatible、Groq 和本地命令 ASR 路径。

原作者版本完成了最关键的产品闭环。VibeStick for Mac 在保留项目历史、署名和 MIT 许可的基础上，继续做 macOS 产品化、安全连接、实机视觉和长期可维护性增强。

## 3. M3-A 实装内容

### 3.1 Codex Focus 真实首页

- 顶部状态栏提高实机可读性，仅保留 `WiFi`、Bridge 状态灯、电量百分比和电池图标。
- 主状态卡以 Codex 图标、`CODEX`、状态灯和中文状态为视觉核心。
- 项目名固定在卡片底部中心，不用移动项目名来补偿左右承重。
- 有项目名与隐藏项目名使用两套布局，隐藏时图标和状态区放大并重新居中。
- 底部操作区压缩为 `SYNC`、`2X REFRESH` 和 `HOLD TO SPEAK`，在低像素屏上保持清晰。

### 3.2 真实 LCD 光学校准

Mac 预览提供方向稿，但最终坐标以真实 StickS3 为准。M3-A 通过多轮实拍逐项调整：

- 顶部 Wi-Fi、Bridge 点、电量百分比和电池图标的光学基线。
- 图标与右侧文字块的左右承重。
- `CODEX` 与不同长度状态文字之间的关系。
- 待命、离线、工作中、已完成、审批、错误等状态的独立 1 px 级补偿。
- 项目名显示/隐藏时的垂直重心。
- 单额度 `7D / LEFT` 的字号差异、基线与左右留白。
- 额度卡高度、百分比、进度条与底栏占用空间。

最终形成的规则是：数学居中不等于视觉居中；同字号不等于同视觉重量；短中文、长中文、英文和图标必须按真实墨量分别补偿。

### 3.3 项目名从协议字段变成实装功能

- Mac App 提供项目名显示开关和固定名称输入。
- 留空时显示 Bridge 当前识别到的运行中 Codex 项目。
- 固定名称与显示开关复用 M2 的 revision/ACK 配置通道，无需重新烧录。
- Mac 预览与设备配置使用同一归一化规则。
- 名称限制为最多 18 个字符、UTF-8 少于 40 字节，防止多字节文本越过固件缓冲区。
- 当前运行任务优先于较新的已完成任务，避免在开发 VibeStick 时错误显示成其他会话项目。

### 3.4 动态额度窗口与刷新策略

- Bridge 输出动态 `quota_windows`，设备按一个或多个有效窗口自动重排。
- 当前 Codex 只有 7D 窗口时，额度卡全宽显示，不为不存在的 5H 保留空列。
- 正常运行时被动读取本地 session `rate_limits` 事件，不额外启动 Codex 进程。
- 双击刷新时才启动一次短生命周期的本地 Codex app-server，只调用账户额度读取方法。
- 主动和被动结果记录来源与观察时间；更新的数据优先，同时间主动账户读数优先。
- 主动刷新失败时保留现有读数并按时间标记陈旧，不破坏首页状态。

### 3.5 Mac 实时预览和配置闭环

- “设备界面”从 M2 草图升级为 Codex Focus 实时预览。
- 项目名开关与固定名称即时反映在预览中。
- 预览表达顶部状态、项目名、单额度布局和底栏操作语义。
- 保存后仍通过 M2 安全配置通道同步，设备回报 revision ACK。

## 4. 相对原作者版本的改进

| 维度 | 原作者版本（上游 `f368d0b`） | VibeStick for Mac M3-A |
| --- | --- | --- |
| 首页结构 | Provider、状态与固定 5H/7D 双栏 | Codex Focus 分层首页，单/双额度自动重排 |
| 项目名 | 状态协议包含项目字段，但首页不展示 | 当前任务或固定名称可显示/隐藏，隐藏后自动重排 |
| 配置方式 | 多数设备视觉调整依赖源码与重新烧录 | 项目设置通过 M2 安全配置通道同步并 ACK |
| Mac 预览 | 没有原生设备配置预览 | SwiftUI 135 × 240 实时预览，与项目设置联动 |
| 小屏适配 | 主要按固定坐标与统一字体布局 | 按状态、字形墨量和实机栅格做独立光学补偿 |
| 额度窗口 | 固定保留 5H 与 7D 两列 | 按真实有效窗口动态展开或分栏 |
| 额度更新 | 本地 session 数据 | 被动 session 为默认，双击时单次主动刷新，按时间防回退 |
| 项目识别 | 使用观察到的最近项目 | 运行中主任务优先，避免已完成的其他任务抢占 |
| 顶部连接状态 | Wi-Fi 与电池为主 | Wi-Fi、Bridge 状态灯、电量与充电图标统一呈现 |
| 验收方式 | 通用布局与功能验证 | 高保真稿、Mac 预览、真机实拍和逐像素人工验收 |

以上比较只描述可从本地上游基线确认的差异，不否定原作者的核心产品设计，也不把 M0-M2 已完成的能力重复包装成 M3-A 新增功能。

## 6. 可用的宣传表达

- **为 135 × 240 真机逐像素打磨：**不是只在设计稿里居中，而是用真实 LCD 反复校准字号、基线、留白和视觉承重。
- **Codex Focus 首页：**状态、项目、额度、连接和语音操作集中在一个清晰首页。
- **项目跟着当前任务走：**优先显示真正运行中的 Codex 项目，不被较新的已完成会话带跑。
- **有多少额度窗口，就显示多少：**单窗口自动展开，双窗口自动分栏，不为不存在的数据浪费屏幕。
- **平时安静，刷新时准确：**默认被动读取、低资源运行；双击时才主动获取更及时的账户额度。
- **Mac 改设置，设备自动同步：**项目名开关通过安全配置通道下发并得到设备 ACK。
- **升级界面，不牺牲稳定核心：**Bridge、HUD、Paste、语音输入、安全配对和提示音持续回归。
