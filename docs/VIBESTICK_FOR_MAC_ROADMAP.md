## 2. 产品定位

VibeStick for Mac 是面向个人使用和朋友小圈子分享的 M5Stack StickS3 桌面 AI 助手增强版。

它不是商业产品，不建设公共服务平台，也不追求覆盖所有设备和所有用户。第一用户始终是项目维护者本人，所有功能优先服务真实、日常、稳定的使用体验。

目标形态：

- 用户下载一个 DMG，并把 VibeStick 拖入“应用程序”。
- Mac 程序统一完成首次配置、权限引导、设备配对、界面选择、语音配置、烧录、更新、恢复和诊断。
- 日常使用不需要终端、Python、ESP-IDF、手动编辑配置文件或查找串口。
- M5StickS3 保持轻量，Mac 负责敏感配置、状态观察、ASR 调用和文本输入。

## 3. 不可妥协的产品原则

### 3.1 稳定基线优先

- 当前已正常工作的 Codex 状态、额度读取、语音输入、Bridge、HUD、Paste 和权限迁移不得无故退化。
- 新 Mac 界面先管理和封装现有稳定核心，不一次性重写全部 Bridge。
- 每个阶段必须可以独立回归测试，并保留回退路径。

### 3.2 本地优先，不提供服务器

- 不提供 VibeStick 中央服务器。
- 不建设账号、云同步、远程控制、在线配置中心或遥测系统。
- StickS3 与 Mac 的运行通信只发生在本地局域网。
- ASR 音频由 Mac 直接发送给用户选择的供应方。
- GitHub 仅用于源码、版本信息、DMG、固件和烧录组件下载。

### 3.3 基础能力不可删除

以下能力属于产品基础层，不能作为普通模块关闭：

- 当前已启用 Agent 的状态。
- 可用的额度或用量窗口。
- 长按设备蓝键录音、转写并输入到 Mac。
- Wi-Fi、Bridge 和设备在线状态。
- 电池、更新时间和必要的错误提示。

### 3.4 可选内容真正模块化

- Agent、附加页面、页面顺序、默认页面、视觉样式、声音样式和实验功能可以配置。
- 被关闭的模块不显示页面、不保留导航入口、不读取凭据、不发送请求，也不运行后台轮询。
- 至少保留一个已启用的 Agent 页面。
- Codex 为默认模块；Claude 作为兼容模块保留，但默认关闭。

### 3.5 敏感信息最小化

- ASR API Key、Bridge 配对密钥等保存在 macOS 钥匙串。
- StickS3 不保存 ASR API Key。
- 日志、诊断包和界面不得显示完整密钥。
- 设备只保存连接当前 Wi-Fi 和已配对 Mac 所需的最少信息。

## 6. 总体架构

~~~mermaid
flowchart LR
  User["用户"] --> MacApp["VibeStick for Mac"]
  MacApp --> Settings["配置与钥匙串"]
  MacApp --> Runtime["后台运行控制"]
  Runtime --> Bridge["内置 VibeStick Bridge"]
  Runtime --> Paste["文字输入服务"]
  Runtime --> HUD["屏幕提示服务"]
  Bridge <--> Stick["M5Stack StickS3"]
  Bridge --> Codex["本机 Codex 状态"]
  Bridge --> ASR["用户选择的 ASR"]
  MacApp --> GitHub["GitHub Releases"]
  GitHub --> Firmware["固件与按需烧录组件"]
~~~

架构原则：

- Mac 前端使用原生 SwiftUI。
- 第一版把现有 Python Bridge 作为应用内部组件封装，用户无需安装 Python。
- HUD、Paste 和 Bridge 由主程序统一显示、启动、停止、检查和修复。
- 普通设置使用统一配置模型，敏感值进入钥匙串。
- 前端通过结构化健康状态管理后台组件，不依赖解析面向用户的杂乱终端日志。
- 只有出现明确的稳定性、性能或体积收益时，才逐步把 Bridge 功能迁移到 Swift。

## 7. Mac 程序信息架构

### 7.1 首页

首页只显示四张核心状态卡：

1. 设备：在线状态、电池、Wi-Fi、Bridge、固件版本。
2. Codex：运行状态、项目名、可用额度窗口和更新时间。
3. 语音：ASR 供应方、配置状态、发送方式和测试入口。
4. 更新：Mac 程序、固件和烧录组件状态。

首页快捷操作：

- 同步设置。
- 测试语音。
- 处理权限问题。
- 安装、更新或修复设备。

正常状态保持安静。只有断连、权限缺失、配置失效、更新失败等情况使用强调色。

### 7.2 侧边栏

- 首页
- 设备界面
- 语音与发送
- 按键与提醒
- 连接与后台
- 更新与恢复
- 高级设置

高级设置包含自定义 ASR、手动 Bridge 地址、诊断导出和技术日志。普通用户不需要进入高级设置即可完成正常安装和使用。

正常界面使用“设备连接服务、屏幕提示服务、文字输入服务”等用户可理解的名称；Bridge、HUD、Paste 等技术名称只出现在展开详情中。

### 7.3 菜单栏与后台生命周期

- 菜单栏入口默认开启，可在设置中关闭。
- 菜单栏显示设备在线状态，并提供刷新、静音和打开控制中心。
- 关闭主窗口不会停止 Bridge、HUD、Paste 或设备通信。
- 明确提供“停止设备服务”，避免把停止后台服务混同于关闭窗口。
- 开机自动运行默认推荐开启，但允许用户关闭。

## 8. 首次安装与权限中心

### 8.1 首次安装流程

1. 打开 Mac 程序。
2. 连接 StickS3 USB-C 数据线。
3. 自动识别设备和已有固件。
4. 如检测到旧版 VibeStick，展示可导入的设置类别并请求确认。
5. 配置 Wi-Fi。
6. 选择设备配置：默认使用 Codex Focus。
7. 配置 ASR。
8. 选择语音发送方式。
9. 选择是否显示项目名。
10. 查看 StickS3 实时预览。
11. 一键安装并完成写入、验证、恢复设置。
12. 进行设备连接、Codex 状态和语音输入测试。

### 8.2 权限中心

权限页面长期保留，不仅出现在首次启动。

每项权限显示：

- 当前状态：已允许、未允许、需要重新确认。
- 用途说明。
- 打开对应系统设置。
- 返回程序后自动重新检测。
- 手动重新检查。

权限策略：

- 辅助功能权限为文字粘贴和模拟 Return 所必需。
- 本地网络权限在首次连接设备时申请。
- 通知权限可选。
- 默认不申请 Mac 麦克风权限，因为录音来自 StickS3。
- 如保留旧版 Mac 麦克风兜底，只能作为默认关闭的高级兼容选项。
- 权限被关闭时，在相关功能被使用时提示，不重复弹窗打扰。
- macOS 系统权限必须由用户在 Mac 上亲自确认，StickS3 按键不能代替系统授权。
- 日常配置和使用不应反复要求管理员密码。

首页只显示权限问题汇总，例如“有 1 项权限需要处理”，点击后进入权限中心。

## 9. StickS3 界面与交互

### 9.1 Codex Focus 固定首页

默认首页结构：

- 顶部：Wi-Fi、Bridge 在线状态、电池。
- 中部：Codex 名称和大号状态。
- 可选：项目名。
- 下部：当前实际存在的额度窗口。
- 底部：更新时间和“长按蓝键说话”提示。

项目名关闭后不得留下空行。Codex 状态区需要重新居中，额度区同步重排。

### 9.2 动态额度窗口

- 额度显示属于基础能力，但不把 5H 固定为必需栏位。
- 固件只渲染 Bridge 实际返回的额度窗口。
- 当前只有周额度时，显示一条全宽周额度。
- 继续解析旧版 5H 和 7D 字段，保证迁移兼容。
- 新协议使用动态 quota_windows 数组，逐步取代固定字段。

建议数据包含：

- 稳定标识。
- 用户可读名称。
- 剩余比例。
- 可选重置时间。
- 数据是否过期。

### 9.3 页面模块与导航

- 页面列表只包含已启用模块。
- 侧面按键切换到下一个已启用页面。
- 只有一个页面时，侧面按键不执行操作，也不播放声音或动画。
- 语音、审批、错误等全屏覆盖层不计入页面列表。
- Claude 关闭后不会出现空白页或切换入口。

首版配置档：

- Codex Focus：默认，仅启用 Codex，并采用重新设计的首页。
- 原版兼容：尽量保留原项目页面和行为，便于迁移与对照。
- 自定义：由用户选择模块、顺序、项目名、按键、声音和视觉偏好。

配置档只保存界面和行为，不复制 API Key 等敏感信息。

### 9.4 语音覆盖层

语音过程临时全屏覆盖，结束后返回 Codex 首页。

简洁状态文案：

- 正在聆听…
- 正在识别…
- 已粘贴
- 按蓝键发送
- 已发送
- 识别失败
- 发送失败

StickS3 不显示完整转写正文。完整文字保留在 Mac 当前输入框中，供用户检查和编辑。

### 9.5 两种发送方式

自动发送：

- 识别成功后粘贴文字。
- Mac 随即模拟一次 Return。

设备确认发送，推荐默认：

- 识别成功后只粘贴，不发送。
- StickS3 显示“已粘贴 / 按蓝键发送”。
- 用户短按一次正面蓝键后，Mac 模拟 Return。

安全规则：

- 只有存在待发送转写时，单击蓝键才能触发发送。
- 待发送动作只允许执行一次。
- 开始下一次录音会使上一次待发送状态失效。
- 尽可能确认仍处于接收粘贴的同一个前台 Mac 应用；无法安全确认时拒绝自动发送。

### 9.6 按键映射

| 场景 | 正面蓝键 | 侧面按键 |
| --- | --- | --- |
| 长按 | 开始录音，松开后结束并识别 | 保留系统电源行为 |
| 有待发送语音时单击 | 发送当前待发送文字 | 切换下一已启用页面 |
| 普通状态单击 | 默认无破坏性动作 | 切换下一已启用页面 |
| Codex 审批待处理时双击 | 仅允许本次 | 不参与审批 |
| 普通状态双击 | 执行用户选择的备用动作 | 不定义双击 |

普通状态双击可选：

- 刷新状态和额度，推荐默认。
- 静音或恢复提醒。
- 重试最近一次失败的连接或同步。
- 打开 Mac 控制中心。
- 运行预先选择的 macOS Shortcut。
- 不执行操作。

按键状态机必须处理防抖、双击等待窗口、长按判定和上下文优先级，避免单击、双击与长按互相误触。

### 9.7 智能双击审批

该能力安排在首个可用版本之后的独立阶段，不阻塞核心版本交付。

只使用官方 Codex App Server 的审批请求和决策接口，不通过：

- 模拟点击 Codex 界面。
- 修改 Codex 会话文件。
- 猜测终端内容。

审批覆盖层只显示：

- Codex 请求权限。
- 请求类型，例如运行命令、修改文件或访问网络。
- 可选项目名。
- “双击蓝键允许本次”。

完整命令和风险详情在 Mac 上查看。

安全约束：

- 设备双击只映射到一次性 accept。
- 禁止映射到 acceptForSession。
- 禁止自动修改长期授权策略。
- 请求必须与 thread、turn 和 item 精确对应。
- 已处理、超时、切换任务或取消的请求必须立即失效。
- 语音待发送上下文优先，避免双击触发无关动作。
- 每个新审批只播放一次既有审批提示音。
- 审批完成、拒绝或过期后短暂显示结果，然后自动返回原页面。
- macOS 辅助功能、本地网络等系统权限不属于设备审批范围。

## 10. ASR 配置

### 10.1 首版预设

- SiliconFlow：FunAudioLLM/SenseVoiceSmall。
- Groq：whisper-large-v3-turbo。
- OpenAI：gpt-4o-mini-transcribe。

预设负责维护 URL、模型、超时、重试和语言默认值。普通用户只需要：

1. 选择供应方。
2. 填写 API Key。
3. 执行一次测试转写。

“获取 API Key”按钮只打开对应供应方的官方页面，不经过 VibeStick 服务器。

预设配置属于 Mac 应用数据，不写死在固件中，以便随供应方变化更新。

### 10.2 自定义供应方

高级设置提供“自定义 ASR 供应方”。

输入项：

- 显示名称，可选。
- Base URL 或完整转写 URL。
- API Key。
- 转写模型名称。
- 语言，可选。

行为规则：

- 尝试通过模型列表自动发现；无法发现时要求用户填写模型名称。
- 支持自动补全 audio/transcriptions 路径，也允许直接使用完整地址。
- 默认要求 HTTPS。
- localhost 可用于本机离线 ASR。
- 测试前显示音频将发送到的目标域名。
- 保存前必须测试成功。
- 第一版界面只管理一个自定义配置，数据模型预留多个命名配置。

### 10.3 错误反馈

区分显示：

- API Key 无效。
- 网络不可达。
- 模型不存在。
- 请求超时。
- 触发限流。
- 响应格式不兼容。

云端 ASR 配置页必须明确说明音频会发送给所选供应方。

## 11. 本地配对、发现与配置同步

### 11.1 首次安全配对

- USB 首次安装时生成设备 ID 和随机配对密钥。
- Mac 保存设备身份和密钥。
- StickS3 只保存发现已配对 Mac 所需的最少信息。
- 用户不需要复制 token 或手动填写 Mac IP。

### 11.2 局域网自动发现

- Mac 使用 Bonjour/mDNS 广播 VibeStick 服务。
- StickS3 自动查找已配对的 Mac。
- Mac 的 DHCP 地址变化后，设备可自动恢复连接。
- 自动发现失败时，高级设置允许手动填写主机地址。
- 更换 Mac 时通过 USB 执行“重新配对”。

不开放公网端口，不使用 UPnP，不支持互联网远程控制。

### 11.3 通用固件与设备配置

- 只维护一套通用基础固件。
- 页面、模块、项目名、按键、声音和显示偏好通过设备配置同步。
- 普通配置变化不需要重新烧录。
- 只有基础固件升级、分区变化或故障恢复才重新烧录。
- Wi-Fi 配置失效时，可以通过 USB 重新配置，而不是完整重装。

## 12. 烧录、更新与恢复

### 12.1 交付策略

- 不把完整 ESP-IDF 打进 DMG。
- 开发机或自动构建流程负责生成固件二进制。
- 稳定固件本身约为 MB 级，可随应用或版本清单提供。
- 官方独立烧录组件在首次使用安装、更新或修复功能时按需下载。
- Apple Silicon 烧录组件预计约 60–70 MB，下载一次后缓存。
- 下载时固定版本、校验 SHA-256，并记录来源。
- 高级设置允许删除和重新下载烧录组件。

### 12.2 安装过程

用户只看到四个阶段：

1. 准备。
2. 写入。
3. 验证。
4. 恢复设置。

界面默认显示简单进度，可展开技术详情。普通模式不显示串口、波特率和烧录命令。

### 12.3 更新策略

- 自动检查更新，但永远不静默烧录设备。
- 用户确认并连接 USB 后才开始固件更新。
- 更新前自动备份配置。
- 更新后验证启动、网络、Bridge、页面配置和语音能力。
- 稳定通道默认开启。
- 测试通道属于高级选项。
- Mac 程序更新与设备固件更新分开管理。
- Mac 程序只提示新版本并打开 GitHub 下载页，不建设复杂更新服务器。
- GitHub 正式 Release 对应稳定版，Pre-release 对应测试版。

### 12.4 故障恢复

- 先区分连接问题、权限问题、配置问题和固件问题。
- 可以修复配置时不重新烧录。
- 必须重装时提供“一键修复设备”。
- 设备无法识别时提供图示恢复模式引导。
- 尽可能保留个人配置。
- 必须清空时明确提示影响。
- 保留上一份可用固件和配置快照，支持回退。
- 失败后提供一键重试和脱敏诊断导出。

## 13. 旧版迁移

Mac 程序首次启动时检测：

- 旧版 .env。
- 已安装的 Bridge、HUD 和 Paste。
- 固件配置和 Bridge token。
- 已有 ASR、项目名、Provider、声音和自动 Return 设置。

迁移流程：

1. 只展示发现了哪些配置类别，不直接显示明文密钥。
2. 用户确认导入。
3. API Key 和 token 迁移到钥匙串。
4. 普通配置进入新配置模型。
5. 保留旧配置备份，直到新版本完整验证成功。
6. 迁移后检查现有辅助功能权限是否继续有效。
7. 失败时允许恢复旧版运行方式。

## 14. 隐私与安全边界

- 无 VibeStick 账号。
- 无 VibeStick 云端。
- 无遥测和自动日志上传。
- 无远程访问和端口映射。
- API Key 不进入固件、日志、诊断包或 Git 仓库。
- Bridge 只接受已配对设备的请求。
- 下载的固件和烧录组件必须校验完整性。
- 诊断包只由用户主动导出，并自动删除密钥、token、Wi-Fi 密码、完整录音和敏感路径内容。
- 当前本地传输以可信局域网为前提，不得暴露到公网。
- 首个小圈子版本发布前完成一次本地传输威胁检查，确认是否需要进一步增加传输加密。
