# VibeStick for Mac M3-B：语音与发送交互规格

> 状态：成功与安全失败主流程及隐私与 UI 收尾已完成真人真机验收；已随 M3-B + M3-C 本地联合检查点封存
>
> 基线：本地提交 `e2113ba`（M3-A Codex Focus）
>
> 本规格最初用于先锁定交互和视觉再进入实现；当前受控部署已经完成，本轮收尾不重新安装 Bridge/HUD/Paste，也不刷写固件。

## 1. 设计目标

M3-B 在不破坏现有长按录音、ASR、HUD/Paste、M2 配对同步和 Codex Focus 首页的前提下，补齐五种用户可见状态：录音、识别、待发送、成功和失败。

设备只显示动作状态，不显示完整转写内容。转写文本继续留在 Mac 当前输入框中，避免小屏字形膨胀、局域网回传和旁观泄露。

## 2. 发送模式

| 模式 | 转写成功后的行为 | 兼容策略 |
| --- | --- | --- |
| 仅粘贴 | 粘贴文字，不按 Return；显示“已粘贴”后返回首页 | 旧配置 `AUTO_ENTER=off` 保持此行为 |
| 蓝键确认 | 先粘贴并进入“待发送”；单击正面蓝键后才按 Return | 新能力，必须由使用者显式选择 |
| 自动发送 | 在同一次 Paste 调用中粘贴并按 Return | 旧配置 `AUTO_ENTER=on` 保持此行为 |

升级不会把“仅粘贴”自动改成“蓝键确认”，也不会自动启用“自动发送”。

## 3. 用户可见覆盖层

| 视觉状态 | 主标题 | 辅助提示 | 自动退出 | 颜色语义 |
| --- | --- | --- | --- | --- |
| 录音 | 正在聆听 | 松开蓝键完成 | 松开进入识别 | 白色波形 + 蓝色活动点 |
| 识别 | 正在识别 | 请稍候 | 完成后进入后续状态 | 蓝色轨道 + 白色核心 |
| 待发送 | 待发送 | 单击蓝键发送 / 长按开始新录音 | 30 秒后失效 | 蓝色确认框 |
| 成功 | 已发送 / 已识别 | 即将返回首页 / 未发送 | 约 1.2 秒 | 绿色确认环 |
| 失败 | 发送失败 | 切回原输入框重试 / 长按可重新录音 | 约 1.5 秒或长按重试 | 红色错误环 |

成功标题可按模式显示为“已粘贴”或“已发送”。失败标题按原因显示为“未听清”“识别失败”“发送失败”或“未发送”，但保持同一版式，避免为每种错误增加独立页面。

## 4. 内部状态机

```text
idle
  -> recording
  -> transcribing
  -> pasted_complete        (仅粘贴)
  -> copied                 (无可用输入框，保留到剪贴板)
  -> pending_send           (蓝键确认)
  -> sending -> sent        (蓝键确认 / 自动发送)
  -> failed

pending_send -> invalidated -> recording   (长按开始新录音)
pending_send -> expired                    (30 秒无确认)
```

每次录音必须绑定唯一 `session_id`。Bridge 只接受当前 session 的确认；重复确认返回相同结果，不会再次按 Return。异步识别结果写回前必须再次检查 session 是否仍然有效，旧任务不得覆盖新录音。

“新录音使旧待发送状态失效”只撤销旧 session 的发送权限，不尝试删除已经粘贴到 Mac 输入框里的文字，避免跨应用模拟删除键造成更大的误操作。

## 5. 按键优先级

| 当前状态 | 正面单击 | 正面双击 | 正面长按 | 侧键单击 |
| --- | --- | --- | --- | --- |
| 首页/空闲 | 保留现有事件 | 保留当前配置动作 | 开始录音 | 切换页面 |
| 录音 | 忽略 | 忽略 | 已处于录音 | 忽略 |
| 识别/发送中 | 忽略 | 忽略 | 忽略，防止并发录音 | 忽略 |
| 待发送 | 确认当前 session | 忽略 | 失效旧 session 并开始新录音 | 忽略 |
| 成功/失败 | 可提前返回首页 | 忽略 | 开始新录音 | 忽略 |

覆盖层可见时，语音状态机优先于页面切换和额度刷新；回到首页后恢复 M3-A 的按键配置。

## 6. 防误发约束

1. 首次粘贴时记录目标 App 的 bundle ID、进程 ID 和可访问性焦点摘要。
   自动粘贴本身不依赖该摘要：只要有辅助功能权限就尽力发送 `⌘V`。如果无法安全绑定
   确认目标，识别仍算成功，文字保留在剪贴板且不进入待发送状态。
2. 蓝键确认时重新检查目标；焦点不一致时拒绝按 Return，并显示“发送失败”。
3. `pending_send` 默认 30 秒过期；过期、Bridge 重启、设备重启或新录音都不会自动发送。
4. 自动发送只在用户明确选择该模式时启用，并在一次 Paste helper 调用中完成粘贴和 Return。
5. 日志只记录 session、状态、耗时、来源和字符数，不记录 transcript、API Key、窗口标题或输入内容。

## 7. 协议兼容方向

| 组合 | 行为 |
| --- | --- |
| M3-A 固件 + M3-B Bridge | 保持现有同步录音/粘贴语义，不出现待发送 |
| M3-B 固件 + M3-A Bridge | 接受旧 `pasted` / 失败结果并正常退出覆盖层 |
| M3-B 固件 + M3-B Bridge | 启用异步状态、待发送、确认、取消和过期 |

M3-B 固件在录音请求中声明交互版本；旧 Bridge 会忽略未知字段。新 Bridge 只对声明新交互版本的固件启用确认状态，避免旧设备进入无法确认的待发送状态。

## 8. 视觉实现约束

- 画布固定为 135 × 240，与当前 StickS3 LCD 一致。
- 背景和主文字继续使用 M3-A 的 `#050608`、`#F4F5F7`；成功 `#32D583`、强调 `#0A84FF`、失败 `#FF5A67`。
- 不在设备显示 transcript；只新增必要的固定中文小字形。
- 动画只使用波形高度、旋转/呼吸和透明度，避免引入大图片或高成本模糊效果。
- 底部状态的圆点与 `HOLDING / WORKING / PENDING / SENDING / DONE / NOT SENT` 文字必须作为一个整体，按 LVGL 实际字宽动态居中；不得用只适合单一单词的固定横坐标。
- 高保真稿中的圆形在真实 LCD 上必须保持视觉正圆；所有底层圆形保持正方形逻辑尺寸，再通过以自身圆心为 pivot 的 LVGL 独立 Y 轴绘制变换作真实 LCD 光学校正。不得用增加 `lv_arc` 对象高度代替变换（arc 只按短边计算半径），也不得把 `LV_RADIUS_CIRCLE` 普通对象改成长方形（会形成胶囊）。真机已把无缩放 `256`（略扁）和 `288`（纵向拉长）确定为两端，经中点 `272` 验收后再轻降至最终校准值 `270`。识别白色核心与蓝色中心点保持名义正圆并严格对齐 arc 的真实圆心，不再附加垂直偏移。失败态感叹号的竖线与圆点必须使用相同的奇数像素宽度和相同 X 中心，避免 `lv_line` 自适应边界与描边外扩造成视觉错位。
- 高保真稿先与真实 M3-A 屏幕并排确认，再受控下发；最终字号、基线和视觉重心已经过真实 StickS3 人工验收。
- 构建时记录新增字形、固件镜像大小和最小 app 分区余量；安全余量不足时停止刷写并单独评审。
- StickS3 使用 8 MB Flash；M3-B 真机版保持既有 NVS/PHY 地址不变，将单 app 分区从
  1500 KiB 扩至 3 MiB。未分配空间留给未来 OTA 或数据分区设计，本阶段不冒充已具备 OTA/回滚。
